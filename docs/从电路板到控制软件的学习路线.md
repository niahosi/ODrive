# 从电路板到控制软件的 ODrive 学习路线

## 1. 这份路线解决什么问题

目标不是照抄一块 ODrive，而是完整理解并亲手走通下面这条链路：

```text
需求与边界
  → 电机、母线和功率器件选型
  → 原理图
  → PCB 与功率回路
  → 板级上电和保护验证
  → PWM 与 ADC 同步
  → 电流采样和标定
  → FOC 电流环
  → 编码器与电角度校准
  → 速度环和位置环
  → Axis 状态机、通信和故障处理
  → 可重复的整机测试
```

完成后，应当能够：

1. 根据目标母线电压、相电流和电机参数画出一块低压双向电机控制板；
2. 解释原理图上每个主要模块存在的原因；
3. 从 PWM 周期追踪到 ADC 采样、FOC 运算和下一周期占空比更新；
4. 用物理单位解释每个控制变量，而不是只会调整无量纲参数；
5. 从波形和运行变量定位“有 PWM 但没有转矩”等问题；
6. 建立明确的上电、校准、闭环、停机和故障恢复流程。

## 2. 版本边界

本仓库公开的是 ODrive v3.x 固件。ODrive Pro、S1、Micro 等新产品的完整固件并未在这里开源。因此：

- 用本仓库理解 v3.x 的真实实现和模块关系；
- 用当前官方文档补充概念、配置方式和新产品行为；
- 不把旧源码中的具体引脚、器件参数和 RTOS 结构直接当成新设计要求；
- 每次借鉴前先提取设计约束，再决定自己的实现。

硬件工程位于相邻仓库：

```text

../ODriveHardware/v3/AuxHalfH.SchDoc
../ODriveHardware/v3/PCB.PcbDoc

```

建议先读 PDF 原理图，再打开 Altium 工程。前者适合建立全局认识，后者适合追网络、封装和 PCB 布局。

## 3. 安全边界

电机驱动器同时包含大电流、快速开关和机械运动，学习样机应限制在自己能够安全测量和切断的低压范围内。

- 初版板不要直接挑战 ODrive 标称的最高电压和电流；
- 使用带电流限制的隔离电源，母线入口设置保险和明确的急停手段；
- 首次上电不装电机、不使能栅极，先检查所有电源轨；
- 示波器地夹不能随意接到开关节点；测高侧和相节点应使用合适的差分探头；
- 功率级运行时，不连接非隔离调试器、USB 或接地仪器形成意外回路；
- 每一级测试都必须有硬件关断路径，软件保护不能替代硬件过流保护；
- 未确认死区、栅极波形和电流采样之前，不进入闭环测试。

本文给的是学习和验证路线，不是可直接量产的安规设计。

## 4. 先建立整机模型

在看代码前，先画出自己的系统框图：

```text
                    ┌──────── 通信与设定值 ────────┐
                    ↓                              │
直流电源 → 母线 → 三相逆变器 → PMSM/BLDC → 机械负载
             ↑          ↑            │
             │          │            ├─ ABZ 编码器
             │          │            └─ 温度
             │          │
             │       三相 PWM
             │          ↑
             ├─ 母线电压│   位置环 → 速度环 → iq 目标
             └─ 相电流 ─┴→ 电流环 FOC → vd/vq → SVPWM
```

随后给每条连线标注四件事：

1. 物理单位；
2. 正方向；
3. 更新频率；
4. 合法范围和故障条件。

这张图是整个项目的“接口合同”。以后遇到问题，沿图寻找第一个输入正确而输出错误的模块。

## 5. 第一阶段：需求和器件边界

### 要回答的为什么

- 为什么先确定母线电压、连续电流和峰值电流，再选 MOSFET？
- 电机的 `Kv`、极对数、相电阻和相电感怎样约束 PWM 频率与供电电压？
- 为什么再生制动会抬升母线，而不是简单地让电机停下？
- 连续电流为什么主要受热限制，峰值电流为什么主要受器件和磁饱和限制？

### 学习输入

- 电机数据：额定电压、`Kv`、极对数、相电阻、相电感、额定/峰值电流；
- 机械数据：目标转矩、转速、惯量、减速比；
- 电源数据：正常电压、最大电压、可吸收回馈电流的能力；
- 环境数据：散热、尺寸、连接器和工作温度。

### 必须产出

建立 `设计约束表`，至少包含：

| 项目 | 最小值 | 典型值 | 最大值 | 单位 | 最大值来源 |
|---|---:|---:|---:|---|---|
| 母线电压 |  |  |  | V | 电源与回馈 |
| 相电流峰值 |  |  |  | A | 目标转矩 |
| 电角频率 |  |  |  | Hz | 转速 × 极对数 |
| PWM 频率 |  |  |  | Hz | 电流纹波与计算预算 |
| 编码器计数率 |  |  |  | count/s | 转速 × CPR |
| 功耗 |  |  |  | W | 导通与开关损耗 |

### 验收条件

能从目标转矩推到所需 `iq`，并说明电源、MOSFET、采样电阻、连接器和铜箔各自需要承受什么。

## 6. 第二阶段：读懂并重画功率硬件

按下面顺序阅读 `ODriveHardware`，不要一开始逐页抄原理图：

1. `v3/v3.5docs/schematic_v3.5.pdf`：建立整板视图；
2. `v3/Top.SchDoc`：理解母线、控制器和两个电机通道的关系；
3. `v3/MotorCell.SchDoc`：理解单个三相逆变器和采样链；
4. `v3/AuxHalfH.SchDoc`：理解制动电阻支路；
5. `v3/PCB.PcbDoc`：对照功率回路、采样回路和控制回路的位置。

### 分块重画

不要直接画完整板，依次做六张小原理图：

1. 母线入口、反接/浪涌处理和母线电容；
2. 一相半桥及栅极驱动；
3. 三相桥；
4. 两相或三相电流采样；
5. 母线电压、温度和故障输入；
6. MCU、编码器、通信、调试和低压电源。

每张图都写一段说明：正常电流从哪里流、故障电流从哪里流、断电后能量到哪里去。

### 关键检查

- MOSFET 耐压要覆盖母线、回馈和寄生尖峰；
- 栅极驱动电压、源灌电流、欠压锁定与死区匹配；
- 自举高侧在目标占空比范围内能可靠刷新；
- 采样电阻的阻值、功率、开尔文连接和共模范围合理；
- ADC 满量程与目标正负电流范围匹配；
- 硬件故障信号能不经主循环立即关闭 PWM；
- 制动支路的电阻、MOSFET 和母线电容能承担回馈能量。

### 验收条件

能够拿着任一相的原理图，讲清楚 PWM 高低电平时的栅极和电流路径；能够从相电流反推出采样电阻电压、放大器输出和 ADC 码值。

## 7. 第三阶段：PCB布局不是原理图的机械翻译

建议先做单轴低压样板，再考虑双轴和高功率密度。

### 布局顺序

1. 固定板框、安装孔、母线和电机端子；
2. 摆放母线电容、三相半桥和驱动器，缩小高 `di/dt` 回路；
3. 摆放采样电阻和放大器，建立独立、对称、短的开尔文采样；
4. 确定功率地、模拟地和数字地的回流路径；
5. 放置 MCU、晶振、去耦、SWD、编码器和通信接口；
6. 最后处理低速信号与机械细节。

### 必须产出

- 顶层和底层电流回流图；
- 三个关键回路的面积对比：栅极回路、半桥换流回路、采样回路；
- 电流密度和温升估算；
- PCB DRC 报告、BOM 和装配图；
- 测试点清单：母线、各电源轨、栅极、三相、采样输出、故障脚、PWM、ADC 触发。

### 验收条件

能解释每个关键器件“为什么放在这里”，而不只是因为布线方便。

## 8. 第四阶段：分级上电

按照以下关卡推进；上一关没有留下测量记录，不进入下一关。

### 关卡 A：无功率级运行

- 不装 MOSFET 或保持栅极驱动禁用；
- 检查所有低压电源和复位；
- 下载最小固件并验证时钟、SWD、UART/CAN；
- 验证故障输入的默认电平。

### 关卡 B：功率级静态检查

- 限流低压供电；
- PWM 保持关闭；
- 检查栅极驱动电源、欠压锁定和静态电流；
- 人为触发故障并确认硬件能关断。

### 关卡 C：不接电机观察 PWM

- 先低占空比、短时间输出；
- 测互补 PWM、死区和栅极电压；
- 检查是否存在上下桥臂重叠导通；
- 验证软件停机和硬件故障都能关闭输出。

### 关卡 D：接电机限流运行

- 使用低母线电压和严格电流限制；
- 先做定子电阻、采样极性和开环电角度验证；
- 再做编码器方向与偏置；
- 最后进入电流、速度、位置闭环。

## 9. 第五阶段：读懂实时链路

先从板级文件追踪中断和外设，再进入算法：

```text
Firmware/Board/v3/Src/tim.c
Firmware/Board/v3/Src/adc.c
Firmware/Board/v3/Src/stm32f4xx_it.c
Firmware/Board/v3/board.cpp
Firmware/MotorControl/motor.cpp
Firmware/MotorControl/foc.cpp
```

重点跟踪下面两条链：

```text
PWM 定时器事件
  → ADC 在指定窗口采样
  → current_meas_cb()
  → 电流值进入控制器

pwm_update_cb()
  → FOC 计算调制量
  → apply_pwm_timings()
  → 定时器预装载寄存器
  → 下一更新事件生效
```

阅读 `motor.cpp` 中 `Motor::arm()` 前面的时序注释，并回答：

- ADC 值对应哪个实际采样时刻？
- FOC 使用的电角度应外推到哪个时刻？
- 运算最迟必须在何时完成？
- PWM 预装载为什么能避免三相占空比在不同时间生效？
- 超时或结果非法时，哪一层负责关断？

### 必须产出

画一张以微秒为单位的时序图，标出：计数器上下数、开关沿、ADC 触发、ADC 完成、FOC 开始/结束和 CCR 锁存。

### 验收条件

能够从 PWM 频率计算一个周期的 CPU 周期预算，并通过 GPIO 翻转或周期计数器测出实际执行时间。

## 10. 第六阶段：电流采样、标定和单位

阅读：

```text
Firmware/MotorControl/motor.cpp
  Motor::phase_current_from_adcval()
  Motor::dc_calib_cb()
  Motor::current_meas_cb()
```

建立完整换算：

```text
ADC 码值
  → ADC 引脚电压
  → 放大器输入差分电压
  → 采样电阻电流
  → 相电流 A
```

必须分别验证：

- 零电流偏置；
- A/B/C 三相符号；
- 两相采样时第三相由 `ia + ib + ic = 0` 重建；
- 满量程与过流阈值；
- PWM 开关噪声对采样窗口的影响；
- 关闭 PWM 后偏置是否漂移。

### 验收条件

串联已知负载或使用可控直流电流时，固件读数与仪表读数在预定误差内，且正负方向一致。

## 11. 第七阶段：FOC 电流环

按以下概念顺序学习：

1. `abc → αβ`：Clarke 变换；
2. `αβ → dq`：Park 变换；
3. `id` 控制磁链，`iq` 控制转矩；
4. `d/q` 电流 PI 产生 `vd/vq`；
5. 电压矢量限幅和积分抗饱和；
6. `dq → αβ` 和空间矢量调制；
7. 调制量变成三相 PWM 比较值。

阅读：

```text
Firmware/MotorControl/foc.hpp
Firmware/MotorControl/foc.cpp
Firmware/MotorControl/motor.cpp
```

必须把代码中的量整理成单位表：

| 量 | 含义 | 单位 |
|---|---|---|
| `Ialpha/Ibeta` | 静止坐标系电流 | A |
| `Id/Iq` | 转子坐标系电流 | A |
| `Vd/Vq` | 电压指令 | V |
| `phase` | 电角相位 | turn 或 rad，依实现确认 |
| `mod_alpha/mod_beta` | 归一化调制量 | 1 |
| PWM compare | 定时器比较值 | count |

### 实验顺序

1. 固定转子，注入很小的 `id`，确认电角度和相序；
2. 固定转子，正负 `iq` 分别产生相反转矩；
3. 低速旋转，观察 `id` 是否接近目标；
4. 逐步提高电流环带宽，观察阶跃和噪声；
5. 验证电压饱和时积分器不会持续累积。

### 验收条件

给定正负 `iq` 时转矩方向稳定可重复，`id` 不因方向变化出现明显直流偏差，电流环阶跃没有持续振荡。

## 12. 第八阶段：ABZ编码器、电角度和校准

阅读：

```text
Firmware/MotorControl/encoder.hpp
Firmware/MotorControl/encoder.cpp
Firmware/MotorControl/axis.cpp
```

先严格区分：

```text
原始计数 count
机械位置 pos
机械速度 vel
机械角 θm
电角 θe
编码器方向 dir
电角偏置 offset
```

基本关系为：

```text
机械转数 = count / cpr
电角转数 = 机械转数 × pole_pairs × dir - offset
```

具体实现可能采用整圈归一化、弧度或定点数，必须以代码接口为准，不能混用。

### 必须理解

- AB 正交计数为什么能判断方向；
- 16 位硬件定时器如何扩展为连续的 32 位位置；
- 跨计数器回绕时为什么要对差值做有符号展开；
- Z 相只提供每机械圈一次的重复参考，为什么不天然等于电角零点；
- 为什么要分别校准编码器方向和转子电角偏置；
- 正反向扫描怎样降低摩擦、齿槽和机械回差造成的偏差；
- PLL 怎样从离散位置得到连续位置和低噪声速度。

### 实验顺序

1. 手转电机，确认计数连续且正反方向正确；
2. 跨越硬件计数器边界，确认位置没有大跳变；
3. 低速搜索 Z 相，确认每机械圈只触发一次；
4. 开环正向和反向扫描电角度；
5. 求编码器方向和偏置，并重复多次观察离散程度；
6. 校准完成后用很小 `iq` 验证正反转矩。

### 验收条件

重复校准得到的方向一致，偏置离散在设定范围内；正负 `iq` 能稳定产生相反转矩；手动正反转经过计数器边界时位置和速度连续。

## 13. 第九阶段：位置、速度、电流三级控制

阅读：

```text
Firmware/MotorControl/controller.hpp
Firmware/MotorControl/controller.cpp
```

控制链为：

```text
位置误差
  → 位置 P
  → 速度目标
  → 速度 PI
  → 转矩目标
  → 扭矩常数换算
  → iq 目标
  → 电流 PI
  → 电压与 PWM
```

每一级都写明：输入单位、输出单位、限幅、更新频率、积分器状态和复位条件。

调参顺序必须由内向外：

1. 电流采样和电角度正确；
2. 电流环稳定；
3. 速度估计可信；
4. 速度环稳定；
5. 最后启用位置环和轨迹规划。

### 验收条件

每一级单独做阶跃响应记录，能区分电流限幅、速度限幅和位置目标本身造成的限制。

## 14. 第十阶段：Axis状态机、保护和通信

阅读：

```text
Firmware/MotorControl/axis.hpp
Firmware/MotorControl/axis.cpp
Firmware/MotorControl/motor.hpp
Firmware/MotorControl/motor.cpp
Firmware/odrive-interface.yaml
Firmware/communication/
```

把对象职责整理为：

```text
Axis
 ├─ 请求状态与实际状态
 ├─ 校准和闭环流程编排
 ├─ arm / disarm
 ├─ watchdog
 └─ 错误汇总

Controller
 └─ 位置环、速度环和 iq 请求

Encoder
 └─ 机械位置、速度、电角度和校准

Motor / FOC
 └─ 电流测量、电流环、调制和 PWM
```

通信协议只应表达控制对象，不应偷偷改变物理意义。对每个协议字段建立表格：

| 字段 | 外部单位 | 内部单位 | 换算位置 | 合法范围 | 写入后影响 |
|---|---|---|---|---|---|

### 必须验证的状态转换

- 上电进入安全状态；
- 未校准时拒绝闭环；
- 校准失败后 PWM 确实关闭；
- 闭环请求、实际闭环和 PWM 激活是可区分的状态；
- watchdog 超时后安全退出；
- 清错不会绕过仍然存在的硬件故障；
- 重新 arm 前积分器和旧设定值按设计复位。

## 15. 第十一阶段：系统化调试

遇到“状态正常但电机不动”，按物理链路检查，而不是随机改参数：

```text
外部指令及单位
  → Controller 输出的 iq_ref
  → FOC 实际收到的 Idq_setpoint
  → Id/Iq 测量值
  → d/q 误差
  → PI 的 vd/vq
  → 电压限幅
  → 电角度及其方向
  → αβ 调制量
  → 三相 PWM 比较值
  → 栅极波形
  → 相电流
  → 机械转矩
```

调试变量至少包括：

- 请求状态、当前状态、armed、PWM active；
- Axis、Encoder、Motor/FOC 各自错误；
- 原始编码器计数、机械位置、速度、电角度、方向和偏置；
- `id_ref/iq_ref`、`id/iq`、`vd/vq`；
- 三相 ADC 原始值、零偏和相电流；
- 三相占空比、母线电压和估算母线电流；
- 每个实时任务的执行时间和超时次数。

第一处“输入符合预期、输出不符合预期”的模块就是主要嫌疑点。

## 16. 建议的十二周实践计划

| 1 | 电机、逆变器与能量流 | 系统框图、单位表 |

每周遵循同一个循环：

```text
  → 回到框图修正理解
```

## 17. ODrive源码阅读顺序

不要按目录顺序通读。推荐顺序如下：

1. `README.md`：确认版本边界；
2. `docs/specifications.rst`：确认旧硬件资料入口；
3. `Firmware/Board/v3/Inc/board.h`：板级资源；
4. `Firmware/Board/v3/board.cpp`：板级运行连接；
5. `Firmware/MotorControl/motor.hpp/.cpp`：采样、PWM、校准和硬件生命周期；
6. `Firmware/MotorControl/foc.hpp/.cpp`：电流环；
7. `Firmware/MotorControl/encoder.hpp/.cpp`：位置、速度和校准；
8. `Firmware/MotorControl/controller.hpp/.cpp`：外环；
9. `Firmware/MotorControl/axis.hpp/.cpp`：状态机和编排；
10. `Firmware/odrive-interface.yaml`：对外对象和单位；
11. `Firmware/communication/`：传输和协议实现。

阅读一个函数时，至少记录：调用者、运行上下文、输入单位、输出单位、状态副作用、错误出口和最坏执行时间。

## 18. 与 O30i 工程的对照学习

可以逐模块将 ODrive 与 O30i 对照，但只比较职责和物理关系，不要求复制类名或 RTOS 框架。

| 学习主题 | ODrive | O30i |
|---|---|---|
| 板级实时入口 | `Firmware/Board/v3/board.cpp` | `Application/Src/board.cpp` |
| 电流采样与PWM | `motor.cpp` | `Application/Src/board.cpp`、`foc.cpp` |
| FOC | `foc.cpp` | `Application/Src/foc.cpp` |
| 编码器 | `encoder.cpp` | `Application/Src/encoder.cpp` |
| 外环 | `controller.cpp` | `Application/Src/controller.cpp` |
| 生命周期 | `axis.cpp` | `Application/Src/axis.cpp` |
| 接口与单位 | `odrive-interface.yaml` | O30i 的 UART/寄存器接口 |

对照时优先回答三个问题：

1. 两边的物理输入和输出是否相同？
2. 两边的调用时刻和 `dt` 是否相同？
3. 两边在失败时是否以同样可靠的方式停止功率输出？

如果这三点不同，就不能只因为函数名相似而认为行为等价。

## 19. 最终毕业验收

最终不是以“电机转了”为完成标准，而是要求：

- 原理图经过逐块审查，所有额定值有计算来源；
- PCB 关键回路、回流路径和热设计有记录；
- 上电测试按关卡完成并保存波形；
- 电流采样有实际标定数据；
- PWM/ADC/FOC 时序有测量而不只是推测；
- 正负 `iq` 的转矩方向稳定一致；
- 编码器回绕、方向、Z 相和电角偏置均经过测试；
- 电流、速度、位置三级环分别有阶跃响应；
- 过流、欠压、编码器断线、通信超时等故障均做过注入；
- 任何故障路径都能可靠关闭功率级；
- 通信字段、内部变量和物理量之间有完整单位表。

达到这些条件后，才算真正从“能画一块板”走到了“理解整套软硬件为什么这样设计”。
